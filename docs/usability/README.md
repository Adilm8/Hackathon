Здесь лежит всё, что нужно, чтобы проверять приложение глазами родителей и детей, а не разработчиков.

| Файл | Что внутри |

## Как проводится проверка

1. Приложение запускается локально (`npm run dev`) и, когда появится, на Railway.
2. Каждый сценарий проходится в четырёх режимах: мобильный Chrome 360×740, iPhone Safari 390×844 (эмуляция WebKit), узкий планшет 768 px, десктоп 1280 px.
3. Для каждой находки записываются: экран, шаги, ожидание, факт, приоритет, скриншот.
4. Сначала проходит сквозной сценарий «Try a sample» за 3 минуты (главный критерий готовности из ТЗ), потом остальные.

## Шкала приоритетов

- **P0, блокер.** Жюри не пройдёт сквозной сценарий или потеряет данные: тупик, пустой экран, неработающая кнопка, сломанная оплата, страх/небезопасный ответ ребёнку.
- **P1, серьёзно.** Путь проходится, но пользователь теряется, ошибается или не доверяет: непонятный текст, мелкие цели нажатия, неясное состояние.
- **P2, заметно.** Раздражает, но не мешает: выравнивание, лишний клик, несогласованные слова.
- **P3, полировка.** Идеи улучшения.

## Что считаем успехом

- Сквозной путь «Try a sample» занимает не более 3 минут без подсказок.
- Новый родитель с первого раза находит «Start for free» и заполняет анкету без ошибок, не связанных с его вводом.
- Ни одного тупика и ни одной неработающей кнопки (жёсткое требование ТЗ).
- Ребёнок 4–6 лет может пользоваться читалкой с родителем рядом: понятные кнопки вопросов, крупные цели нажатия.
- Родитель понимает, что именно изменилось в следующей странице из-за вопроса ребёнка.
